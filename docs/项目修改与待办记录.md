## 1. 已完成：将 Embedding 配置为智谱官方 API

已修改根目录 `.env`，使用智谱官方接口进行文档和查询向量化。当前配置如下（不记录 API 密钥）：

```dotenv
RELAY_BASE_URL=https://open.bigmodel.cn/api/paas/v4
EMBEDDING_PROVIDER=relay
EMBEDDING_MODEL=embedding-3
EMBEDDING_DIM=2048
RERANKER_ENABLED=false
```

`relay` 是当前项目已有的客户端分支名称；实际请求直接发送至智谱官方，不再经过第三方中转站。`RELAY_API_KEY` 应填写智谱官方密钥。主力对话继续使用 DeepSeek。

已同步 `.env.example`、Python 配置默认值、doctor 默认接口与模型，以及 pi-agent 默认接口地址和相关说明。默认使用智谱 `embedding-3`、2048 维及 `rerank`，API 重排序默认关闭。客户端分批与重排序映射逻辑尚未修改；遗留 `RELAY_MODEL` 保留并明确标注，等待后续可选化改造。此次同步未执行真实 API 调用。

## 2. 潜在问题与后续改进

### 2.1 Embedding 批量输入和长度限制

状态：暂缓处理。

智谱 `embedding-3` 输入数组最多 64 条，每条输入最多 3072 tokens。当前客户端会一次发送传入的全部文本，未自动分批，也未按模型 token 限制校验单条输入。

较长文档可能超出限制，调用失败后当前实现会回退 hash 向量。后续应增加分批请求、输入长度检查，以及返回向量数量与维度校验。当前使用默认 2048 维；`EMBEDDING_DIM` 并不会作为 `dimensions` 参数发送给服务端，不能仅修改该配置来要求远程模型降维。

相关代码：`backend/app/llm/relay.py`、`backend/app/llm/embeddings.py`、`backend/app/pipeline/indexer.py`。

### 2.2 Rerank 返回分数与原候选的映射

状态：暂缓修复，已通过 `RERANKER_ENABLED=false` 避免启用 API 重排序。

智谱返回结果包含 `index` 与 `relevance_score`。当前代码只提取分数，再按原候选顺序配对，可能将分数分配给错误文档。

后续应按 `index` 对齐分数，校验索引范围、重复项和结果完整性，并处理候选最多 128 条、查询与单条候选最多 4096 字符的限制。修复并验证后再启用 `RERANKER_ENABLED=true`。

关闭 API 重排序时，项目仍使用本地启发式重排序，并非完全不排序。

相关代码：`backend/app/llm/relay.py`、`backend/app/retrieval/reranker.py`。
