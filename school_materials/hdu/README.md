## 可入库材料

`department_files/杭州电子科技大学/` 内有7份Markdown：上述6份官方材料正文（有附件的同时包含附件文本）以及1份校历转录。正文仅提取官网文章区，保留办理步骤、链接、数字及联系方式，排除导航、脚本与页脚。原始Word表格保留在 `originals/电子信息学院/`，填写、打印时使用原件；转写文本用于检索。

部门归属：证明书补办与校历归教务处，图书馆指南归图书馆，学院发布的研究生办事材料归电子信息学院。部门ID沿用原配置；图书馆新增为 `dept_tsg`。安全部门名称为“安全保卫部”，“保卫处”为术语别名。

自动部门路由和意图识别的关键词回退同步更新为杭电场景，涵盖证明书补办、图书馆/CARSI、导师变更、增退修、用印、自助打印和“保卫处”，避免只命中无对应材料的部门。

## 更新与导入

在项目根目录运行 `python3 school_materials/hdu/prepare_materials.py` 可校验并重新生成正文与清单。已有原件不会重复下载；Word文本提取使用macOS自带textutil。

Docker镜像重建后，同步资料并仅导入这批新素材：

```bash
docker compose up -d --build backend worker pi-agent
docker compose exec backend python -m scripts.seed_data
docker compose exec backend python -m scripts.ingest_department_files --base /app/department_files/杭州电子科技大学
```

不要把`originals/`作为导入目录，以免网页与附件重复进入检索。旧示例目录仍保留，使用上述限定目录可以避免将旧样例一起导入。`seed_data`现会保留已有部门管理员、审核统计、阶段及Agent配置。

## 素材导入阶段验证记录（2026-10-21）

本节及 `verification.json` 保存前端适配前的素材导入验证快照。后续校标蓝主题和聊天页面修复见项目提交记录；下文构建方式为当时的环境记录。

已同步学校资料并限定目录导入7份文档，全部为active、向量ready；共19个切片和19条向量。32项相关测试通过，包括重复同步不覆盖既有部门治理状态、部门目录映射和三个场景的路由回归。原始文件、附件与入库文本的SHA-256校验均通过。

通过真实登录和问答接口验证证明书补办、图书馆校外访问、导师变更表单、2026年春季开课及暑假日期四个问题，4/4引用到预期文档。校历回答为2026-03-05开课、2026-07-06开始放暑假。验证使用的临时会话按`hdu-verify-`前缀清理，不保留为学生演示历史。

素材导入时，标准Docker构建因镜像仓库网络不可达而失败，使用本机现有镜像作为底层，仅叠加应用文件完成离线更新；Agent仅同步与源码一致的两处名称文本，并通过JavaScript语法检查。该阶段未修改前端源码及镜像，后续已完成前端适配。日常启动和重新构建请使用根目录README中的命令。
